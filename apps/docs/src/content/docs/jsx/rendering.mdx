# JSX Client Rendering

This page is about the client entrypoints. Import from `@ecopages/jsx` or `@ecopages/jsx/client`; keep `@ecopages/jsx/server` in server-only modules.

- mount new DOM with `createRoot(...).render(...)`
- hydrate existing SSR markup with `hydrate(...)` or `createRoot(...).hydrate(...)`

For server HTML generation, see [JSX SSR](/docs/ssr/jsx-ssr).

## Direct DOM Rendering

Use `createRoot(...)` when you want to mount JSX directly outside a Radiant custom-element host.

```tsx
/** @jsxImportSource @ecopages/jsx */

import { createRoot } from '@ecopages/jsx';

function App() {
	return <p>Hello JSX</p>;
}

const container = document.querySelector('#app');

if (container instanceof HTMLElement) {
	createRoot(container).render(<App />);
}
```

The root API is intentionally small:

- `render(element)` mounts or updates the target
- `hydrate(element)` attaches bindings onto matching SSR output
- `unmount()` disposes the mounted tree and clears the target

## Hydrating Existing Markup

Hydration is the client attach step for markup that was produced with `renderToString(..., { mode: 'hydrate' })`.

```tsx
/** @jsxImportSource @ecopages/jsx */

import { createRoot } from '@ecopages/jsx';

function App() {
	return <p>Hello JSX</p>;
}

const container = document.querySelector('#app');

if (container instanceof HTMLElement) {
	createRoot(container).hydrate(<App />);
}
```

You can also call `hydrate(element, target)` directly.

```tsx
/** @jsxImportSource @ecopages/jsx */

import { hydrate } from '@ecopages/jsx';

function App() {
	return <p>Hello JSX</p>;
}

const container = document.querySelector('#app');

if (container instanceof HTMLElement) {
	hydrate(<App />, container);
}
```

If the target does not contain hydration markers, counting those inside nested custom elements, the runtime falls back to a normal client render.

For render-owning `RadiantElement` custom-element hosts, there is one extra gate: the explicit Radiant hydrator must also be installed. See [Hydration](/docs/ssr/hydration).

## Checking SSR Output

Use `hasHydrationMarkers(...)` when you need to detect whether a target contains SSR binding markers before attempting client attach behavior.

```tsx
/** @jsxImportSource @ecopages/jsx */

import { createRoot, hasHydrationMarkers } from '@ecopages/jsx';

function App() {
	return <p>Hello JSX</p>;
}

const container = document.querySelector('#app');

if (container instanceof HTMLElement && hasHydrationMarkers(container)) {
	createRoot(container).hydrate(<App />);
}
```

## Signals

`@ecopages/jsx` reads signals directly: pass a value with `get()` and `subscribe(...)`, such as a `state` or `computed` from `@ecopages/signals`, as a child or an attribute value, and the renderer subscribes to it and patches that one text node or attribute when it changes. No Radiant host is needed.

So the usual shape is to render once and let signals carry every later change:

```tsx
/** @jsxImportSource @ecopages/jsx */

import { state, type State } from '@ecopages/signals';
import { createRoot, MapItems } from '@ecopages/jsx';

type Row = { id: number; label: State<string>; cls: State<string> };

const rows = state<Row[]>([]);

createRoot(document.querySelector('#app') as HTMLElement).render(
	<table>
		<tbody>
			<MapItems each={rows}>
				{(row) => (
					<tr classes={row.cls}>
						<td>{row.id}</td>
						<td>{row.label}</td>
					</tr>
				)}
			</MapItems>
		</tbody>
	</table>,
);

rows.set([{ id: 1, label: state('first'), cls: state('') }]);
rows.get()[0].label.set('renamed'); // patches one text node
rows.get()[0].cls.set('selected'); // patches one class attribute
```

- **Children:** `{row.label}` binds the text; a signal that holds JSX mounts and reconciles it in place.
- **Attributes:** a signal works as any attribute value, as well as in `attr:`, `bool:` and `prop:` bindings. A reactive class goes in `classes`: its value is normalized like a static one, so it can hold a string, a list or a class map. `class` takes a plain string, so a wrapper can merge it with its own classes. A style signal can hold a string or a style object.
- **Lists:** `<MapItems each={rows}>` renders each item once and reuses that row while the item stays in the list, so a swap or a removal touches only the rows that moved or left. Rows are keyed by their item automatically; a row with its own `key` keeps it. The callback runs untracked, so reading an item's signals there does not subscribe the view. Bind the signals in the row, as `row.label` above, to keep them live. `each` must be a signal or subscribable holding an array.

The list state lives with the `each` signal, so a view that renders again, such as a Radiant host `render()` or a second `root.render(...)`, keeps the same rows and subscription. Outside JSX, `mapItems(rows, (row) => row.label)` from `@ecopages/signals` does the same mapping and returns a `Computed`.

A `computed` that calls `.map` over the rows still works, but it rebuilds the JSX of every row on each list change. In it, pass the signal, not `signal.get()`: reading values while it builds the rows makes the list depend on every one of them.

The renderer skips a keyed row whose value is the same object it rendered last time. A new object with equal values is still applied in full, so controlled inputs keep working. `MapItems` relies on this by returning the same row object for an unchanged item.

The alternative is to call `render(...)` again with fresh JSX on every change. That works, since the renderer patches what changed, but every render rebuilds and compares the whole tree. Use it for small or rarely changing views, and signals for anything that updates often.

### Keyed fragments

`<Fragment key=...>` groups several nodes under one key. When keyed siblings reorder, the group moves as a single entry.

```tsx
/** @jsxImportSource @ecopages/jsx */

import { Fragment, MapItems } from '@ecopages/jsx';

<dl>
	<MapItems each={terms}>
		{(term) => (
			<Fragment key={term.id}>
				<dt>{term.name}</dt>
				<dd>{term.description}</dd>
			</Fragment>
		)}
	</MapItems>
</dl>;
```

### Other update sources

Wrap a source that has its own change notifications but no `get()`/`subscribe(...)` pair with `createSubscribableJsxValue(...)`:

```tsx
/** @jsxImportSource @ecopages/jsx */

import { createRoot, createSubscribableJsxValue } from '@ecopages/jsx';

const clock = createSubscribableJsxValue({
	getValue: () => new Date().toLocaleTimeString(),
	subscribe: (notify) => {
		const timer = setInterval(() => notify(new Date().toLocaleTimeString()), 1000);
		return () => clearInterval(timer);
	},
});

createRoot(document.querySelector('#app') as HTMLElement).render(<p>{clock}</p>);
```

## Empty Values During Updates

See the Empty Values And Removal section of [JSX Overview](/docs/jsx/overview) for the full rules. The sign-in button below applies them across two client updates:

```tsx
/** @jsxImportSource @ecopages/jsx */

import { createRoot } from '@ecopages/jsx';

const root = createRoot(document.querySelector('#app') as HTMLElement);

type SignInState = {
	username: string;
	busy: boolean;
};

const signIn = () => console.log('sign in');

const renderSignInButton = (state: SignInState) => (
	<button
		type="button"
		disabled={state.busy || state.username === ''}
		on:click={state.busy ? undefined : signIn}
		title={state.username === '' ? 'Enter your username first' : undefined}
	>
		{state.busy ? 'Signing in...' : 'Sign in'}
	</button>
);

root.render(renderSignInButton({ username: '', busy: false }));
root.render(renderSignInButton({ username: 'ada', busy: true }));
```

How each removal rule applies between those two renders:

- `disabled={...}` — evaluates to `true` while the username is empty or a request is in flight; when it evaluates to `false`, the boolean attribute is removed
- `title={... ? '...' : undefined}` — `undefined` removes the attribute once a username exists
- `on:click={... ? undefined : signIn}` — `undefined` detaches the handler while a sign-in request is in flight
- child text swaps between the two states as normal content

`title` and `on:click` are bound in the first render and dropped from the second because their values are `undefined`. The renderer keeps the same `<button>` node and removes the attribute and the listener, so focus on the button survives. The tag and the number of child slots decide whether the element is reused, not the set of bound attributes.

## Runtime Output Contract

`jsx()` and `jsxs()` return a template result object with:

- static string segments
- dynamic values
- a stable marker used by the Radiant renderers

The distinction between `jsx()` and `jsxs()` is important:

- `jsx()` is emitted when the source has one logical child value
- `jsxs()` is emitted when the source has multiple sibling children

Radiant uses that distinction to preserve child-slot structure from the automatic JSX transform.
