# @query

`@query(selector)` reads the first element matching a CSS selector, or `null`. `@queryAll(selector)` reads every match in document order, `[]` when nothing matches. Both are getters that run the lookup on every access, with no cache, and both work on `RadiantElement` and `RadiantController`.

Both are unscoped: a selector reaches into nested hosts, so it can find an element another host owns. To read the `data-ref` parts a host owns, use [@ref](/docs/decorators/ref) and [@refAll](/docs/decorators/ref).

## `@query`

```typescript
import { RadiantElement, customElement, query } from '@ecopages/radiant';

@customElement('user-profile')
export class UserProfile extends RadiantElement {
	@query('[data-avatar]') avatar!: HTMLImageElement | null;
	@query<HTMLButtonElement>('button.action') submitButton!: HTMLButtonElement | null;

	focusAvatar() {
		this.avatar?.focus();
	}
}
```

The type argument is the element type. Under standard decorators the field must accept `null`, and any other field type does not compile: see [Typing Decorated Fields](/docs/decorators#typing-decorated-fields).

## `@queryAll`

```typescript
import { RadiantElement, customElement, queryAll } from '@ecopages/radiant';

@customElement('item-list')
export class ItemList extends RadiantElement {
	@queryAll<HTMLLIElement>('li.item') items!: HTMLLIElement[];
}
```

The field is an array of elements, rebuilt on every read. Under standard decorators any other field type does not compile.

## Parameters

| Parameter | Type | Required | Description |
| :-------- | :--- | :------- | :---------- |
| `selector` | `string` | Yes | CSS selector to match elements within the host. |

## Part Scope

A selector is not scoped. `@query('[data-ref="root"]')` finds the first `root` in the host, including one inside a nested Element Host or Controller Host. `@ref('root')` finds only the `root` part the host owns, and skips a nested host's. Use `@query` when reaching into a nested host is what you want, and `@ref` otherwise.

## `@query` vs JSX Bindings

`@query` is for reading DOM you do not directly control from `render()` — content projected into a slot by a consumer, DOM enhanced by a `RadiantController`, or a live `Element` handle needed by a third-party imperative API (positioning libraries, focus management, observers).

If the host does **not** override `render()`, copy the field with [@bindTo](/docs/decorators/bind-to) instead of querying a node only to write into it.

If the element is one your own `render()` JSX produces, prefer a binding instead of querying it back out to write into it:

```tsx
// Avoid — re-fetching a host-rendered node just to write into it
@ref('count') countEl!: HTMLElement | null;

@onUpdated('count')
syncCount() {
  if (this.countEl) this.countEl.textContent = String(this.count);
}

override render() {
  return <span data-ref="count"></span>;
}
```

```tsx
// Prefer — bind the value directly at the JSX position
override render() {
  return <span>{this.$.count}</span>;
}
```

The binding patches just that text node when `count` changes; the query-and-write version does the same job with more code, an extra DOM read, and no benefit. Reach for `@query` or `@ref` when there is no reactive value to bind: you need the node itself, not a value at that position.
