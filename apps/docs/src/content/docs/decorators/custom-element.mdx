# @customElement

The `@customElement` decorator provides a concise way to register custom elements with the browser's Custom Elements registry. It is a declarative wrapper around the standard `customElements.define()` API.

## Legacy decorators

With legacy decorators, `@customElement` returns and registers a subclass of your class, so reactive setup runs when construction finishes and a value assigned right after `new` wins over an authored attribute, as with standard decorators. Decorator syntax is unaffected, and `customElements.get(tag)` is that subclass. When you call the decorator imperatively, use the returned class:

```ts
const Foo = customElement('x-foo')(class extends RadiantElement {});
```

Setup runs only for the class that is constructed. A subclass of a decorated class, decorated or not, keeps its reactive accessors: it defines its own fields after the base constructor returns, so the setup waits for the most derived decorated class, or for connect when none is decorated.

## Usage
```typescript
import { RadiantElement, customElement } from '@ecopages/radiant';

@customElement('my-component')
export class MyComponent extends RadiantElement {
	override connectedCallback() {
		super.connectedCallback();
		this.textContent = 'Hello from my-component!';
	}
}
```
Usage in HTML:
```html
<my-component></my-component>
```

## Parameters

| Parameter | Type | Required | Description |
| :-------- | :--- | :------- | :---------- |
| `tagName` | `string` | Yes | The custom element tag name. |
| `options` | Autonomous custom-element options | No | Options for defining an autonomous custom element, plus `hostAttributes`. |

## Host Attributes

`hostAttributes` gives every instance fixed attributes, such as an ARIA landmark role:

```typescript
@customElement('app-sidebar', { hostAttributes: { role: 'complementary' } })
export class AppSidebar extends RadiantElement {}
```

- Server rendering writes them while it prepares the host, so the server output carries them before any script runs.
- In the browser they are written at the start of every connect, before `onConnected()`.
- An attribute the author already wrote is kept: `<app-sidebar role="navigation">` stays a navigation landmark.
- A subclass inherits its base class's attributes, and its own `hostAttributes` override them by name.
- Only `RadiantElement` hosts apply them. Use `@bindTo` or `@onUpdated` for attributes that depend on state.

The custom elements specification forbids adding attributes in the constructor, which is why the attributes wait for connect or server preparation.

## Customized Built-in Elements

`@customElement` supports autonomous custom elements only. TypeScript excludes `extends` from its options, and passing a defined `extends` value at runtime throws a `TypeError` before registration. Extend `RadiantElement` to create a custom button or another autonomous element.
