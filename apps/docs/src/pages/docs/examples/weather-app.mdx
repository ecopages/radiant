# Weather App

This example stays small on purpose.

<WeatherApp />
<br />

It uses:

- a `RadiantComponent` host that owns the JSX view and the context provider
- `createResource(this, {...})` to drive abortable Open-Meteo requests from the selected city
- stale-while-revalidate rendering so the previous forecast stays visible during refetches
- a delayed loading overlay that only appears when the request outlives `pendingDelay`
- a `@contextSelector` field on the host that holds the current context snapshot for `render()`
- a second `RadiantComponent` summary card that subscribes to the visible report slice via a `@contextSelector` field — no `@consumeContext` needed

## Why This Example Exists

The weather app is the smallest example in the docs where context still feels justified.

The host owns the query lifecycle and city picker. The summary card only cares about the visible report, so it subscribes to that slice via a field and reads `this.visibleReport` directly during render. It does not need the provider reference at all.

## Async Strategy

The host declares one sourced resource via `createResource(this, {...})` from the selected city signal. Source changes abort older requests automatically, cached results can resolve synchronously, and successful responses update the shared context via `this.provider.setContext(...)`.

The city list, forecast shaping helpers, and shared types live beside the script in `weather-app.utils.ts` and `weather-app.types.ts`. The example below focuses on the Radiant-specific part.

## Example

```tsx
import {
	type ContextProvider,
	RadiantComponent,
	contextSelector,
	createContext,
	customElement,
	provideContext,
} from '@ecopages/radiant';
import { createResource } from '@ecopages/radiant/signals/host-resource';
import { state as signalState } from '@ecopages/signals';
import type { WeatherCity, WeatherContext, WeatherReport } from './weather-app.types';
import {
	DEFAULT_CITY_ID,
	WEATHER_CITIES,
	fetchWeatherReport,
	getWeatherCity,
	upsertWeatherReport,
} from './weather-app.utils';

const weatherContext = createContext<WeatherContext>(Symbol('weather-context'));

@customElement('radiant-weather-summary')
export class RadiantWeatherSummary extends RadiantComponent {
	@contextSelector({
		context: weatherContext,
		select: ({ visibleReport }) => visibleReport,
	})
	visibleReport: WeatherReport | undefined;

	override render() {
		if (!this.visibleReport) return null;

		return (
			<article data={{ city: this.visibleReport.city }}>
				<p>{this.visibleReport.city}</p>
				<p>{this.visibleReport.temperature}°C</p>
				<p>{this.visibleReport.summary}</p>
			</article>
		);
	}
}

@customElement('radiant-weather-app')
export class RadiantWeatherAppElement extends RadiantComponent {
	private activeCityId = signalState(DEFAULT_CITY_ID);

	@provideContext<typeof weatherContext>({
		context: weatherContext,
		initialValue: {
			activeCityId: DEFAULT_CITY_ID,
			reports: [],
			visibleReport: undefined,
		},
	})
	provider!: ContextProvider<typeof weatherContext>;

	private weatherQuery = createResource(this, {
		pendingDelay: 500,
		staleTime: 60_000,
		source: (ctx) => ctx.host.activeCityId.get(),
		fetcher: (cityId, ctx) => fetchWeatherReport(getWeatherCity(cityId), ctx.signal),
		onSuccess: (report, ctx) => {
			ctx.host.provider.setContext({
				activeCityId: report.cityId,
				reports: upsertWeatherReport(ctx.host.provider.getContext().reports, report),
				visibleReport: report,
			});
		},
	});

	@contextSelector({ context: weatherContext })
	weatherState: WeatherContext = {
		activeCityId: DEFAULT_CITY_ID,
		reports: [],
		visibleReport: undefined,
	};

	private readonly handleCityClick = (event: Event) => {
		const button = event.currentTarget as HTMLButtonElement | null;
		const cityId = button?.dataset.cityId;
		if (!cityId) return;
		this.activeCityId.set(cityId);
		this.provider.setContext({ activeCityId: cityId });
	};

	override render() {
		const status = this.weatherQuery.status.get();
		const { activeCityId, reports, visibleReport } = this.weatherState;
		const activeCity = getWeatherCity(activeCityId);
		const activeReport = reports.find((report) => report.cityId === activeCityId);
		// ...
	}
}
```

## What This Example Should Teach

- `@contextSelector` on a field replaces the previously empty-method pattern. The host and the summary card both declare fields and read from `this.*` in `render()` — no method body, no `this.update()`.
- The summary card does not need `@consumeContext` because it only reads. `@contextSelector` alone is sufficient for read-only consumers.
- The host still uses `@provideContext` and gets a `provider` field because it calls `provider.setContext(...)` on success and on city click. Read access and write access are separate concerns.
- `createResource(this, {...})` keeps the async lifecycle inside the host without manual cleanup.
- `render()` is enough for this kind of interactive custom element. No imperative DOM sync step is needed.
