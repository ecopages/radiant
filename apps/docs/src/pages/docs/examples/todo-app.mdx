# Radiant Todo App

This is the integration example, not the first base-class example.

<RadiantTodoApp />

It combines three different jobs in one flow:

- an SSR-friendly wrapper that emits initial markup and hydration data
- a `RadiantComponent` host that owns the board view and rerender boundary
- `RadiantElement` leaf items that handle lower-level DOM interaction

## Why This Example Exists

The todo app is useful because it shows that `RadiantComponent` and `RadiantElement` are complementary.

`RadiantComponent` is not replacing the item element here. The host and the leaf nodes solve different problems.

## 1. SSR Wrapper Markup

The wrapper emits initial HTML plus hydration data.

```tsx
import { stringifyTyped } from '@ecopages/radiant/tools/stringify-typed';

export const RadiantTodoApp = () => {
	const data = getData();
	const incompleteTodos = data.todos.filter((todo) => !todo.complete);
	const completedTodos = data.todos.filter((todo) => todo.complete);

	return (
		<radiant-todo-app class="todo">
			<section class="todo__board">
				<TodoPanel title="Incomplete Todos" count={incompleteTodos.length} ref="incomplete">
					{incompleteTodos.length > 0 ? <TodoList todos={incompleteTodos} /> : <NoTodosMessage />}
				</TodoPanel>
				<TodoPanel title="Completed Todos" count={completedTodos.length} ref="complete">
					{completedTodos.length > 0 ? <TodoList todos={completedTodos} /> : <NoCompletedTodosMessage />}
				</TodoPanel>
			</section>
			<TodoForm />
			<script type="json" data-hydration>
				{stringifyTyped<Partial<TodoContext>, string>({ todos: data.todos })}
			</script>
		</radiant-todo-app>
	);
};
```

That part is about SSR and first paint, not about replacing `RadiantElement`.

## 2. RadiantComponent Host

The host owns shared state, context, and the top-level JSX render loop.

```tsx
import {
	type ContextProvider,
	RadiantComponent,
	contextSelector,
	createContext,
	customElement,
	onEvent,
	provideContext,
} from '@ecopages/radiant';

export const todoContext = createContext<TodoContext>(Symbol('todo-context'));

@customElement('radiant-todo-app')
export class RadiantTodoApp extends RadiantComponent {
	@provideContext<typeof todoContext>({
		context: todoContext,
		initialValue: { todos: [], logger: new Logger() },
		hydrate: Object,
	})
	provider!: ContextProvider<typeof todoContext>;

	@onEvent({ selector: 'form', type: 'submit' })
	submitTodo(event: FormDataEvent) {
		event.preventDefault();
		const form = event.target as HTMLFormElement;
		const formData = new FormData(form);
		const todo = formData.get('todo');

		if (todo) {
			const prevTodos = this.provider.getContext().todos;
			const todos = [...prevTodos, { id: Date.now().toString(), text: todo.toString(), complete: false }];
			this.provider.setContext({ todos });
			form.reset();
		}
	}

	@contextSelector({ context: todoContext })
	onTodosUpdated() {
		this.update();
	}
}
```

This is exactly where `RadiantComponent` is strongest: the host owns the view and rerenders explicitly through `render()` and `update()`.

## 3. RadiantElement Leaf Nodes

Each todo item stays a `RadiantElement` because it is a lower-level custom element with its own DOM queries and event handling.

```tsx
import {
	type ContextProvider,
	RadiantElement,
	consumeContext,
	customElement,
	onEvent,
	prop,
	query,
} from '@ecopages/radiant';

@customElement('radiant-todo-item')
export class RadiantTodoItem extends RadiantElement {
	@query({ selector: 'input[type="checkbox"]' }) checkbox!: HTMLInputElement;
	@prop({ type: Boolean, reflect: true, defaultValue: false }) declare complete: boolean;
	@consumeContext(todoContext) context!: ContextProvider<typeof todoContext>;

	override connectedCallback(): void {
		super.connectedCallback();
		this.complete = this.checkbox.checked;
	}

	@onEvent({ selector: 'input[type="checkbox"]', type: 'change' })
	toggleComplete(event: Event) {
		const checkbox = event.target as HTMLInputElement;

		this.context.setContext({
			todos: this.context
				.getContext()
				.todos.map((todo) => (todo.id === this.id ? { ...todo, complete: checkbox.checked } : todo)),
		});
	}
}
```

This element does not need its own host JSX render loop to be valuable.

## What This Example Should Teach

- `RadiantElement` does not need SSR in order to work.
- `RadiantComponent` is the host-owned render mode built on top of `RadiantElement`.
- A larger app often uses both together.
- SSR, slots, and leaf custom elements are different concerns and do not need to be collapsed into one base class explanation.

If you are learning the base classes, start with [Radiant Counter](/docs/examples/counter). If you want the mixed architecture example, this todo app is the right next step.
