# Introduction

Radiant is a light-DOM custom-element toolkit with three package layers that work together:

- `@ecopages/radiant` for custom-element classes, decorators, lifecycle, context, and host rendering behavior
- `@ecopages/jsx` for TSX authoring, DOM mounting, SSR serialization, and hydration helpers
- `@ecopages/signals` for renderer-agnostic signals, effects, watchers, and stores

## Start Here

The default path today is:

1. Install `@ecopages/radiant` and `@ecopages/jsx`
2. Build host views with `RadiantComponent`
3. Use `@prop` for public API and `@state` for internal state
4. Reach for `RadiantElement` only when the host is primarily imperative or string-template based

## Why Light DOM

Radiant deliberately embraces the light DOM instead of making shadow DOM the default.

That is a good fit when you want:

1. Global styling without shadow-boundary workarounds
2. Easier integration with existing CSS and DOM tooling
3. A smaller runtime model centered on browser primitives
