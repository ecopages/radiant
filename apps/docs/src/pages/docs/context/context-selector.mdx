# @contextSelector

Use `@contextSelector(...)` when a method should run with the current context value, or a selected slice of it.

## Options

| Option | Type | Description |
| :-- | :-- | :-- |
| `context` | `Context` | The context token to resolve |
| `select` | `(context) => unknown` | Optional projection that narrows the resolved value before delivery |
| `subscribe` | `boolean` | Whether client-side subscriptions stay active after the first value |

## Example

```typescript
import { RadiantComponent, contextSelector, customElement } from '@ecopages/radiant';

import { todoContext } from './todo-context';

@customElement('todo-summary')
export class TodoSummary extends RadiantComponent {
	@contextSelector({
		context: todoContext,
		select: ({ todos }) => ({ count: todos.length }),
	})
	onTodoCountChanged({ count }: { count: number }) {
		this.dataset.count = String(count);
		this.update();
	}
}
```

`select` is useful when the method should react to a stable derived slice rather than the whole context object.

```typescript
@customElement('todo-summary')
export class TodoSummary extends RadiantComponent {
	@contextSelector({
		context: todoContext,
		select: ({ todos }) => ({
			completed: todos.filter((todo) => todo.complete).length,
		}),
	})
	onCompletedCountChanged({ completed }: { completed: number }) {
		this.dataset.completed = String(completed);
	}
}
```

## Subscribe Behavior

On the client, the decorated method keeps receiving updates according to the `subscribe` option. During SSR, the method can also run when an ambient provider is available.

## When To Use It

- Use `@contextSelector(...)` when a method should react to context changes.
- Use [@consumeContext](/docs/context/consume-context) when the host needs the provider object itself.
