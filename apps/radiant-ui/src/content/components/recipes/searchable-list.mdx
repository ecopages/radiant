# Searchable list

<p class="docs-lede">A search field that narrows a list as you type, and arrow keys that walk what is left.</p>

## Goal

A command list, a country picker or a long settings page: type to narrow, press the Down arrow to leave the field and walk the matches, press Enter to choose. The list is always on the page, so there is no popup to open or close.

## Primitives

- [textContains](/docs/helpers/text-filter) decides whether an item matches. It ignores case and accents by default, so `creme` finds `Crème brûlée`.
- [RovingController](/docs/controllers/roving) gives the visible matches one tab stop and moves it with the arrows. `getItems` returns only the visible items, so the arrows skip what the filter hid and `sync()` after each filter keeps the tab stop on a visible item.

It does not use a combobox popup, where a field keeps focus while a popup of options is navigated with `aria-activedescendant`. A list that is already on the page needs no popup, and moving real focus with the roving controller is less code.

Left to the recipe: reading the query, hiding the items that do not match, the Down arrow that moves from the field to the list, and what choosing does.

## Example

Type to filter, press ArrowDown to move into the list, use the arrow keys, and press Enter to choose. Pick an authoring pattern below; they all behave the same, and the one you pick is remembered on the other recipes.

<RecipePatterns patterns={['element', 'component', 'controller', 'plain']}>

<RecipePattern id="element">

The same behavior as a `RadiantElement`. The markup is authored inside the element and the element finds its parts with `@query`; there is nothing to mount, clean up or run again.

<RecipeExample recipe="searchable-list" pattern="element" layout="stack" />

<RecipeCode recipe="searchable-list" pattern="element" />

`createRovingController(this, ...)` attaches the controller when the element connects and destroys it when the element disconnects, and `@onEvent` listeners follow the same lifecycle. So removing the element undoes everything, and the router adding a copy on another page starts it again without a mount call. `sync()` goes in `onConnected` because the items exist only after the element has its children.

What the Radiant form removes: the `mount` function and its registration, the cleanup to return and call, and the re-run after a client-side navigation.

</RecipePattern>

<RecipePattern id="component">

The same behavior as one self-contained element. The list is not authored on the page: the element holds the fruit and the query as state and draws the label, the field, the rows and the status line in `render()`.

<PrimitiveExample host layout="stack">
	<searchable-list-app></searchable-list-app>
</PrimitiveExample>

<RecipeCode recipe="searchable-list" pattern="component" />

Filtering writes `query` and `status`, and `render()` draws only the matching rows, so a hidden item is no longer an element with `hidden` set but a row that is not there. A render replaces the rows the roving controller knew, so `updated()`, which runs after each commit, calls `sync()` to put the tab stop back on a row that exists. The list is drawn by the first render, after the controller attached on connect and found nothing to listen on, so `updated()` attaches it again. The `input` is not bound to state, so typing never replaces the field and focus stays in it.

Compared with the Radiant element above, the markup and the data live inside the element, so there is nothing to keep in step with the page, but restyling the structure means editing the class. It also needs the render path to have content before the script runs: this docs build prerenders the tag empty and the client draws it, so the page shows nothing until the script loads, which a page of authored children does not.

</RecipePattern>

<RecipePattern id="controller">

The same behavior as a `RadiantController` attached to markup that already exists. The root is a plain `div` carrying `data-controller="searchable-list"`, and the class finds its parts with `@query` just as the element does.

<RecipeExample recipe="searchable-list" pattern="controller" layout="stack" />

<RecipeCode recipe="searchable-list" pattern="controller" />

There is no custom element tag to define, so the markup can come from a server template or a CMS and the class attaches to it through `data-controller`. One registry that the docs site starts over the document connects it, including copies inserted later. `createRovingController(this, ...)` takes the controller as its host exactly as it takes the element, so the logic is the element form's, and removing the root runs the same cleanup.

</RecipePattern>

### Styles

The stylesheet is the `searchable-list.css` tab in the files above. It styles the field, the rows and the status from the theme variables, and marks the row that holds the tab stop with `:focus-visible`, so the walked row needs no class the script would have to keep in step. The selectors are scoped to the example on this site; drop the scope in your own project.
