# Agent tools

<p class="docs-lede">
	A cart that the person and a browser agent both add to, through the same method, with the agent's tool present
	exactly while the cart is on the page.
</p>

> Experimental. [WebMCP](https://developer.chrome.com/docs/ai/webmcp) is an origin trial and may change, and the helpers here follow it.

## Goal

A page that lets an agent do what a person does: add a product to the cart, close a dialog, filter a list. The agent calls a tool the page registered, instead of finding and clicking the DOM. The tool belongs to the component that owns the state, so it appears when the component connects and goes when it is removed, and the button and the tool run the same code.

## Primitives

- [`@agentTool`](https://github.com/ecopages/radiant/blob/main/packages/radiant/README.md#agent-tools-experimental) turns a method into a tool. The method stays an ordinary method, so the form submit calls `addItem` with a typed argument and the agent calls the same method.
- `registerAgentTool` registers a tool without a host and returns the function that removes it. The plain form uses it, and the decorator is built from it through `createAgentTool(host, config)`, which ties a tool to an element's connect and disconnect.
- A schema library describes the input once. This recipe uses [Zod](https://zod.dev): `z.toJSONSchema(schema)` gives the `inputSchema` the browser shows the agent, and `schema.parse` goes in `parse`, which checks what the agent sent before the method runs. Radiant takes plain JSON Schema and a `parse` function, so Valibot, ArkType or hand-written code work the same way.

Left to the recipe: the schema, what the method does, and what it returns. The tool name is unique on the page, so a component that can appear twice builds the name from an instance value, and types the host parameter because the decorator is written before TypeScript knows the class:

```ts
@agentTool({
	name: (host: AgentToolsElement) => `add_to_cart_${host.id}`,
	description: 'Adds a product to the cart by its SKU.',
})
addItem(item: Item) {}
```

## Example

Add a product with the form, or call the tool from the inspector below the example, which stands in for an agent. The inspector lists the page's tools and calls one with the JSON in its box. A call that fails the schema is rejected before the method runs, so the cart does not change and the agent receives an error. This page uses a small stand-in for `document.modelContext` where the browser has none; the recipe code never touches it.

## What to watch for

- **Unique names.** A second registration with the same name is rejected by the browser, and Radiant reports it with the tool and the element. Two UIs that do the same thing use two names, or one owner registers the tool once.
- **Validate in code.** `inputSchema` is advisory, so an agent can send anything. `parse` is where the input is checked, and a method that skips it receives the input as sent.
- **Return when the page is true.** Update the UI before the method returns, and return a value that says what happened, because the agent reads it.
- **Embedded pages.** A tool registered inside an iframe needs `allow="tools"` on the frame.
- **Server-rendered elements.** A host that waits for its children registers its tool only after it hydrates.

## Keeping data safe

A tool runs page code for an agent, and what it returns can leave the device. Radiant has no tool that reads the page, so a tool exposes only what you return from it. The full list is in the [package README](https://github.com/ecopages/radiant/blob/main/packages/radiant/README.md#agent-tools-experimental); the ones this recipe shows:

- **Say what it changes.** The tool sets `annotations: { consequentialHint: false }`: adding to a cart is easy to undo. An action that is hard to undo sets `consequentialHint: true`, and one that changes nothing sets `readOnlyHint: true`. In development a tool with neither hint logs a warning.
- **Return the least.** `{ count }` is all the agent needs. Never return tokens, secrets or the contents of password, card or one-time-code fields, and set `untrustedContentHint: true` on output that carries text a user or another site wrote, because an agent may treat tool output as trusted.
- **Ask for the least.** The schema asks for a SKU and nothing about the person.
- **Confirm in your own UI.** The current WebMCP spec has no confirmation API. A consequential tool awaits the app's own dialog inside `execute` and closes it when the `signal` aborts.
- **Authorize on the server.** The agent can skip the checks the UI does, so a real cart checks permission on the server and binds a consequential call to an id or version.
- **Keep it on this origin.** Tools are visible only to the page's own origin. `exposedTo` lets other origins call them with arguments you cannot trust, and logs a warning in development.
