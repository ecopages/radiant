# Video player store

<p class="docs-lede">
	The same player as [Video player](/docs/recipes/video-player), with the snapshot in one store so a binding such
	as `this.$.media.muted` patches a node without redrawing the stage.
</p>

## Goal

The original component already binds the clock with `this.$`, so a playing clip does not redraw the stage. Mute and speed still do, because `render()` reads those `@state` fields. This recipe keeps the same controls, keyboard, captions and fullscreen, and holds the snapshot in one `createStore`. A binding such as `this.$.media.muted` follows that path, so mute and speed patch without a render. Clicking play still redraws once, because the error panel's `hidden` follows `media.stage` (see the component notes below). The [Video player](/docs/recipes/video-player) component form is the baseline this one is measured against.

The store is a component-form technique: `render()` owns the tree, and `this.$` patches it. The element and controller forms of the original player already write the DOM without `render()`, so this page has the component form, and the plain form of the original player as its baseline.

## Primitives

- [MediaController](/docs/controllers/media) owns playback, as on the original player. `onState` and `onProgress` write paths on the store; they do not call `render()`.
- [CaptionsController](/docs/controllers/captions) owns the captions. The recipe writes `media.captionsOn` from the state it reports.
- [formatMediaTime](/docs/helpers/media-time) is applied with `this.$.media.position.map(formatMediaTime)`, so the clock is a projection of one field.
- [cycleValue](/docs/helpers/overview) steps the speed button.
- `createStore` from `@ecopages/signals` holds the snapshot. A binding such as `this.$.media.muted` updates when that path changes.
- [`rui-slider`](/docs/forms/slider) takes `max`, `disabled` and `value` as a snapshot: its view helper stamps them on its parts when `render()` runs. So they come from private fields that `render()` reads, and each callback also writes the current value on the slider by hand. The buffered layer stays a node the recipe inserts, because the slider has no region for it.

Left to the recipe: the same keyboard, auto-hiding controls, fullscreen, live region and Blob load as the original, with the data and the loader of the [Video player](/docs/recipes/video-player). The volume slider's level (`0` while muted) and the seek thumb's time text are computed in the callbacks and written to the sliders, because the slider takes them as a snapshot.

## Example

Press Play or click the video, drag the scrub bar, change the volume, cycle the speed and turn the captions on. The behavior is the same as the video player; the difference is where the snapshot lives.

`render()` never reads a store path. `{this.media.position}` would subscribe the whole view to every frame; `{this.$.media.position}` patches one node. `map` covers a single-field projection such as each clock. `stage` is one store path, written from the controller's status in the same callback as the rest of the snapshot.

The one render that clicking play still costs comes from the error panel: `hidden` is a standard boolean attribute, and the JSX runtime reads the current value of a binding on one while `render()` builds the tree, to choose a presence binding, so `render()` follows `media.stage`. The fullscreen button's `hidden` does the same with `media.fullscreenAvailable`, once when the element connects. A binding on any other attribute, such as `data-state`, does not.

`render()` still reads private fields for the sliders: `seekMax` and `seekable` so the helper can stamp `max` and `disabled` when the clip is ready, and `position` and `level` so a render keeps the thumbs where they are. The fields are not reactive, so writing them per frame runs no render; `requestUpdate()` runs only when the clip becomes seekable. A value written only on the slider would not last: the next render puts the helper's snapshot back. The per-frame `value`, the buffered layer and the thumb's `aria-valuetext` are written to the slider by hand: those nodes are not positions in this host's tree that a binding can own. `data-controls-hidden` is a store path, so a touch tap hides or shows the bar in the same turn without waiting for a render. `fullscreenchange` writes `media.fullscreen` the same way.

Compared with the original component, mute and speed no longer redraw the stage: they are bindings too. Clicking play still redraws once, for the error panel's `hidden`. The cost is the slider writes the helper still forces, and one render when the clip becomes seekable.
