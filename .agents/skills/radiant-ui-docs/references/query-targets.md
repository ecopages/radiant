# Query targets

Hard rule for Radiant UI behavior hosts. Docs, TSDoc, and scripts share this dialect.

## What a host may query

| Kind               | When                                                                         | Example                                                            |
| ------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `[data-ref="…"]`   | Stable region of the composed tree (shell, track, trigger wrapper, column).  | `[data-ref="track"]`, `[data-ref="trigger"]`, `[data-ref="field"]` |
| Dedicated `data-*` | Semantic identity or a named control the author opts into.                   | `[data-tag]`, `[data-select-trigger]`, `[data-value]`              |
| Role               | APG item identity when that is the real target (no extra data attr).         | `[role="option"]`, `[role="menuitem"]`, `[role="tab"]`             |
| Child tag          | Nested host. Name extra selectors the **parent** reads on that child's tree. | `rui-listbox`, `[data-select-value] rui-tag-group`                 |

`@query({ ref: 'root' })` is `[data-ref="root"]`. Prefer `data-ref` for any node that is only a structural hook.

## What a host must not query

- BEM class names (`.rui-foo`, `.rui-foo__bar`, `.rui-foo--x`).
- Tailwind or incidental classes.
- Presentation modifiers the host itself toggles (`rui-sidebar__menu-button--active`). Write the class; query a `data-ref` / `data-*` / role.

If a script still has `querySelector('.rui-…')` or `@onEvent({ selector: '.rui-…' })`, that is a bug. Migrate to `[data-ref]` (or an existing dedicated `data-*` / role) **before** documenting the contract. Do not publish a class name as a public target.

Tests and Storybook `play` functions may assert on BEM for visuals. Host behavior must not.

## `data-ref` naming

- One value is unique **inside that host's authored tree**. Nested hosts keep their own refs; the parent must not collide with them.
- `[data-ref="root"]` is this host's outermost shell (popover anchor, carousel region). Do **not** stamp a parent column as `root` if a child host already uses `root` (select, combobox). Use a distinct name (`field`, `list`, `track`).
- Reuse names that already exist on the view (`trigger`, `surface`, `content`, `pane`) rather than inventing a parallel attr.
- Identity (`data-value`, option text) stays on dedicated attrs, not on `data-ref`.

## Host writes vs queries

Writing a class for presentation is allowed (`rui-button--md` on a cycle button, `rui-slider--vertical` on a root). Querying that class is not.

In TSDoc `@remarks`, do not paste “BEM classes live on the view; the host never queries them” as a mantra. Either it is true for **this** host, or you still have a class selector to delete.

## Dual fallbacks

Do not keep `getRef('form') ?? querySelector('form.rui-form')`. One target. The view stamps it; custom markup stamps the same `data-ref`.

Label discovery uses `[data-rui-field-label]`, not `label.rui-label`.

## Derived Tree

Inner nodes generated by `render()` still use `data-ref` / `data-*` for the host's own queries. Document them as generated — authors do not stamp them. Parents that embed the host (date-field → calendar days) name the extra selectors they read on the child's generated tree.
