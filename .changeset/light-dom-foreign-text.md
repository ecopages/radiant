Security fix: SSR no longer lets Authored Children text create elements when it sits in a `style`, `script`, `xmp`, `iframe`, `noembed` or `noframes` tag inside `svg` or `math`. Those tags are ordinary elements there, so their text is now entity-escaped, anywhere under `math` (including `mi` and `mtext`) and under `svg` outside `foreignObject`, `desc` and `title`. In HTML they stay raw text, and only a matching closing tag (`</style` followed by whitespace, `/` or `>`) is rewritten, also when it is split across text nodes, so CSS such as `@media (width < 600px)` is emitted unchanged. Parsed markup such as `<svg><style>a&amp;b</style></svg>` now decodes its character references there, as browsers do, so changing it does not double-escape the text. Inside `svg` and `math` the server DOM also reads comments and `<![CDATA[…]]>` sections as browsers do, so a `</style>` inside them no longer ends the element, and a changed SVG icon keeps its CDATA-wrapped CSS.
