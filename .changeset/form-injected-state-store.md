`rui-form` can drive a form state store it did not create. Call the new `form.connect(store, { formatError, submitHandler, resetHandler })`, the only way to inject a `FormStateStore`, and the form becomes a control bridge. `connect` returns a disposer that returns the form to its own store in the state it was left, and the handlers are typed by the store's own issue type. A control change calls `setValue(path, value, { native })`, blur calls `blur(path, { value, native })` with the value only when the user changed it, and submit writes every control the user changed and then either calls the new `submitHandler({ store, validate, readNativeValidity, focus, submitNatively })` or awaits `validate(undefined, { native })` and emits `rui-submit` or `rui-invalid`. `native` is the control's own validity (`{ type, params?, message? }` with the failing `ValidityState` flag as `type` and the constraint, such as `{ minLength: 8 }`, as `params`; `null` when valid), read from native `input`, `textarea` and `select` and from form-associated hosts, and it always travels in the same call as the value or event it describes; the `native` record on `validate` is authoritative, and `rui-form.readNativeValidity()` writes the controls the user changed and returns it for a host that validates itself. A control's fact is also reported on its own, with `reportNative(path, native)`, when it is seeded and whenever the store's value at its path changes, so the store always holds current facts; the store binds it to the value it holds without counting a change, re-validates only a path already validated or failed, and ignores a path it does not hold. A report the store rejects is reported with `reportError` and does not stop the others. The store owns validation timing, touched and dirty state, defaults and which errors and warnings show, so `mode`, `revalidate-mode`, field `defaultValue`, `defaultValues`, `resolver` and field `rules` are ignored while a store is injected. The snapshot carries `values`, `errors` and `warnings`: a warning never blocks submit and shows in the new `RuiFieldWarning` region without marking the control invalid. `resetHandler({ store })` takes over the native `reset` event, and `formatError(issue, { path })` receives the store's whole entry and produces the text for errors and warnings; `FormStateStore<TIssue>` is generic over the entry type and `connect` infers it, with no cast. The `formatError` property applies to the form's own store. Without `connect` the form behaves as before, apart from the breaking changes below.

Breaking changes, and how to migrate:

- The built-in `FormStore` nests values by dotted path: a field named `profile.name` is `values.profile.name`, and `rows.0.title` is `values.rows[0].title`. `getValues()`, `getSnapshot().values`, `rui-submit` values, `defaultValues`, `defaultValuesData`, rule `validate` callbacks and resolvers all see the nested tree. HTML `name` attributes, and the keys of `errors`, `touched` and `dirty`, stay dotted. Before, such a name was one literal flat key. Read nested values, or keep flat names without dots.
- `FormContextActions.register` returns a handle, `{ rename(name), unregister() }`, instead of an unregister function. Replace `const off = actions.register(r); off()` with `const handle = actions.register(r); handle.unregister()`.
- `FormContextValue.store` is widened from `FormStore` to `FormStateStore`. Code that reads `FormStore`-only members such as `getValues()` from the context must narrow with `instanceof FormStore`.
- An entry in an errors record marks its field invalid even when its `message` is missing or empty (before, a rule or resolver error without a message was ignored). An error from `FormStore.setErrors` replaces the store's own error at that path, the source set most recently wins, no message is borrowed between them, and the error clears when the user edits that field; until then it blocks a built-in submit.
- Native `input`, `textarea` and `select` validity (`required`, `type="email"`, `minlength`, `pattern`, ...) now counts as an input to validation, so a built-in form with such attributes blocks submit and shows the error the browser's `validationMessage` gives. Before, only form-associated hosts reported validity. A `resolver` cannot disable it: remove the attributes instead. A rule or resolver message replaces the native text but still blocks. The error `type` is now the failing `ValidityState` flag (before, `native`), and no `Invalid value` text is invented when a control has no message.
- Object-valued props no longer read JSON from kebab-case attributes. `rui-field` `rules` and `default-value`, and `rui-form` `default-values`, `resolver` and `format-error` are property-only. Pass them with `prop:` bindings or properties, `data-default-values` for form defaults, and `data-default-value` for a field default.
- A custom (third-party) control host is written only on its bubbling `rui-change`, not on the native `input` event that reaches the field before the host has updated its value. Emit `rui-change` after the host commits a value.
- `FormStore.setValue` is a change: it marks the field dirty and validates per `mode`, where before it only wrote the value.
- `FormStore.errors` is now an accessor, so a subclass that declares `errors` as a property no longer compiles.
- `FormStore.setValue` takes a string path, the typed `errors`, `touched` and `dirty` records are keyed by string paths, and `FormStore.handleSubmit`'s `onInvalid` receives an optional second argument, the error a validator threw.

`FormStore` implements `FormStateStore` and gains `getValue`, `getSnapshot`, `blur`, `validate`, `reportNative`, `readNativeValidity` and `setErrors`.

Fixes that ship with it. A `rui-field` no longer unregisters and registers again on its first name update, which briefly dropped its value from the built-in store; a real rename goes through the registration handle in one notification, and two keyed rows can swap names without losing a registration. And a submission always settles: `FormStore.isSubmitting` stays true until an awaited `onSubmit` finishes and is always cleared, a validator that throws ends the submission with `rui-invalid` whose `detail.error` holds the thrown value, and an `onSubmit` rejection is reported with `reportError` instead of becoming an unhandled rejection.

Two more fixes. A `rui-field` no longer writes a composite control (a checkbox group, a multi-select) on the capture-phase native `input` event, before the control has committed its value: such a control reports through `rui-change`, so one toggle is one write and an untouched group writes nothing. And the object-valued props of `rui-field` (`rules`, `defaultValue`) and `rui-form` (`defaultValues`, `resolver`, `formatError`) are property-only (`attribute: false`), so they are never serialized to or read from an attribute.
