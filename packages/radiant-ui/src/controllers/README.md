# Controllers and helpers

The reusable primitives components are built from. Read this table before writing bespoke logic: most behaviors a new component needs already exist as a tested controller or helper.

Two entries, both tree-shakeable (a bundle contains only what it imports):

| Import path                        | Holds                                                                                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `@ecopages/radiant-ui/controllers` | `controller`: stateful classes attached to a host, with `createX` factories, plus the DOM utilities they are built from. Needs a browser. |
| `@ecopages/radiant-ui/helpers`     | `helper`: pure functions and types. No DOM at import time, so they run on the server and in tests. Dates, masks, numbers, ordering math.  |

Entry sources: [`../controllers.ts`](../controllers.ts) and [`../helpers.ts`](../helpers.ts). They are named so the package `sideEffects` entry for built `index.js` files does not match them.

Contract, `Controller`, `bindController`, compose-or-extend and the protected hooks: [Controllers in the catalog README](../components/ui/README.md#controllers).

## Composing a component from primitives

1. Name the behaviors: open and close, keyboard movement, dragging, filtering, date math, positioning.
2. Pick one primitive per behavior from the tables below. Controllers own the DOM wiring; helpers own the decisions and formatting.
3. Hold the controllers in fields of the custom element with `createX(this, config)`. Config is getters (`getItems`, `getTarget`) and callbacks (`onChange`), so the element keeps its own state and the controller never reaches into it.
4. Keep what is specific to the component (state, markup, `rui-change` events) in the component. Use a helper, not a controller, for anything that only maps input to output.
5. If a decision needs to differ, use a config callback first, a documented `protected` hook by subclassing second, a new controller last.

Example, "a calendar with draggable events and a filter":

- Month grid, selection, headers: `buildCalendarMonth`, `getWeekdayLabels`, `formatMonthYear`, `addMonths`, `toggleMultipleIso` or `advanceRangeSelection` (`helper`).
- Arrow keys across the day cells: `createRovingController` with all days as one flat list and `orientation: 'none'`, moving by your own row and column math, or `navigateRovingTabindex` for one axis (`controller`).
- Dragging an event to another day: `createSortableController` with a `SortableGroup` shared by the day containers (`controller`), or `createPointerDragController` with `elementUnderPointer()` for free-form drops, then `dateToIso` for the target day (`controller`, `helper`).
- Filtering events by text: `textContains` (`helper`).
- Event details in a popup: `createPopoverController` (`controller`).
- Re-render when events are added: `createMutationController` (`controller`).

## Controllers

Each class has a `createX(host, config)` factory that attaches on connect and destroys on disconnect. `host` is a `RadiantElement` or anything with `registerConnectedCallback` and `registerCleanupCallback`. Without a host, construct the class and call `attach()` and `destroy()`.

| Export                                                                                         | What it does                                                                                                                       | Reach for it when                                                                  | Key config                                                                                  |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `bindController`, `Controller`, `ControllerHost`                                               | The contract and the connect and cleanup wiring behind every factory.                                                              | You write a new controller or hold one without a factory.                          | `bindController(host, controller)`                                                          |
| `EventListenerController`, `createEventListenerController`                                     | Listens to one or more event types on a target while attached; typed from target and type.                                         | Listeners on `document` or `window`, added and removed at runtime, or with `once`. | `getTarget`, `type`, `listener`, `options`                                                  |
| `MutationController`, `createMutationController`                                               | A `MutationObserver` on a node.                                                                                                    | React to children or attributes changing.                                          | `getTarget`, `options`, `onMutate`                                                          |
| `ResizeController`, `createResizeController`                                                   | A `ResizeObserver` on elements.                                                                                                    | React to an element changing size.                                                 | `getTargets`, `onResize`                                                                    |
| `DismissController`, `createDismissController`                                                 | Reports a pointer press outside a surface, focus leaving it, or Escape.                                                            | A dialog, drawer or popup that closes itself.                                      | `getSurface`, `getRelated`, `getOpen`, `onDismiss`, `triggers`                              |
| `PopoverController`, `createPopoverController`                                                 | Portal mount, floating position, dismissal and teardown of a popup.                                                                | A popup, hover card or menu panel beside an anchor.                                | `getAnchor`, `getFloating`, `getOpen`, `getPlacement`, `gap`, `portal`, `onDismiss`         |
| `PortalController`, `createPortalController`                                                   | Moves a node into `document.body` (or a container) and carries the origin theme.                                                   | A surface that must escape clipping or stacking contexts.                          | `getNode`, `getContainer`                                                                   |
| `FocusTrapController`, `createFocusTrapController`                                             | Keeps Tab inside a modal surface and returns focus on destroy.                                                                     | A modal dialog.                                                                    | `getSurface`, `getFocusable`, `getStrict`                                                   |
| `ScrollLockController`, `createScrollLockController`                                           | Locks page scroll, counted across controllers.                                                                                     | A modal that must stop the page scrolling.                                         | none                                                                                        |
| `RovingController`, `createRovingController`                                                   | Roving tabindex with arrows, Home and End, over the items `getItems()` returns.                                                    | Tabs, toolbars, lists, grids with one tab stop.                                    | `getItems`, `getTarget`, `orientation`, `wrap`, `onMove`                                    |
| `SwipeController`, `createSwipeController`                                                     | Reports a left, right, up or down swipe on release.                                                                                | A carousel or pager.                                                               | `getTarget`, `axis`, `threshold`, `exclude`, `onSwipe`                                      |
| `PointerDragController`, `createPointerDragController`                                         | Pointer capture, move, end and cancel; reports position, delta and the element under the pointer.                                  | A slider, splitter, resize handle or free-form drag.                               | `getTarget`, `canStart`, `capture`, `onStart`, `onMove`, `onEnd`                            |
| `SortableController`, `createSortableController`, `SortableGroup`, `DEFAULT_SORTABLE_MESSAGES` | Reorder items, or move them between containers, by pointer or keyboard with announcements. It never moves a node: `onChange` does. | A reorderable list or board, including drag between lists.                         | `getContainer`, `getItems`, `group`, `axis`, `liftKeys`, `onChange`, `announce`, `messages` |
| `ListboxPopoverController`, `createListboxPopoverController`                                   | Active-descendant navigation and popup positioning for a listbox.                                                                  | A select or combobox you build from options.                                       | `getAnchor`, `getFloating`, `getOpen`, `getOptions`, `getActiveDescendantHost`              |
| `MenuTreeController`, `createMenuTreeController`                                               | Nested submenu coordination: timers, keyboard, popovers.                                                                           | A menu button or menubar with submenus.                                            | `root`, `getRootMenu`, `onActivate`, `onCloseRoot`                                          |
| `CalendarPopoverController`, `createCalendarPopoverController`, `focusCalendarPickerDay`       | Open state, positioning, focus-out dismissal and mobile layout for a calendar popup.                                               | A date picker popup around a calendar.                                             | `getHost`, `getAnchor`, `getFloating`, `getOpen`, `setOpenState`                            |

The hooks a subclass can override, and the types their signatures use, are exported with the controllers: `PopoverController.position`, `DismissController.isInside`, `RovingController.resolveNext` (`RovingNavResult`, `RovingOrientation`), `PointerDragController.acceptsPress`, `SwipeController.resolveDirection` (`SwipeDirection`) and `SortableController.resolveTargetIndex` (`SortableRect`).

## Internal

Not exported from either entry; do not import them from `dist` or `src` in consumer code.

- `ListboxHostController` (`components/ui/shared`): reads `RuiListbox` host types from the catalog.
- `preview-timing`, `multi-value`, `field-label` and `form-owner` in `components/ui/shared`: catalog-specific.

## Adding a primitive

Add the export to `src/controllers.ts` or `src/helpers.ts`, give it TSDoc with a short `@example` where the usage or result is not obvious (controllers: the `createX` call; helpers: an input and output line), and add a row here. A pure module goes in `helpers`; anything that touches the DOM when called goes in `controllers`.
